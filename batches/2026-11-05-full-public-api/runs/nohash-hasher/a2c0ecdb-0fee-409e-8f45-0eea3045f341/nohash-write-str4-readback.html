Overview

For nohash-hasher 0.2.0 on x86_64 with std enabled or disabled, Default initializes the stored value to zero, Clone preserves state, and finish returns the stored integer. Each of the ten integer write methods stores the Rust conversion of its input to u64: unsigned values are widened and signed values are converted modulo 2^64. With debug assertions enabled, the first integer write succeeds and a later write fails its assertion. With debug assertions disabled, each integer write replaces the stored value. The generic byte-slice write always panics in both configurations. These are exact per-method state and result contracts over all inputs, proved from unchanged published Rust bodies. Separate original-body Kani evidence checks handwritten Debug::fmt for NoHashHasher<u8> after Default or one arbitrary write_u8, using default {:?} formatting into a fixed 64-byte writer. Successful output has exact tuple delimiters, canonical decimal state and, in debug mode, the correct written flag. A writer that errors on its first call propagates Err and leaves its buffer unchanged. All std/no_std dependency and debug/release combinations pass separately: 2175 debug and 2143 release checks in each feature configuration; the verification harness itself uses std. This is a bounded formatter/input-domain supplement, not another Aeneas API claim or a proof for arbitrary stored u64 values, writers, formatting options or partial-write failures. A separate Kani supplement executes the actual standard Clone::clone_from default body and original manual Clone for NoHashHasher<u64>, in all four configurations. Source and destination independently begin at Default or one arbitrary write_u64. Public finish checks destination replacement and source preservation; a distinct full-original-prefix fixture with read-only getters also checks the debug written flag. The eight jobs succeed (public-value stage 47 debug or 28 release checks, flag-observer stage 104 or 81 checks per feature configuration). This concrete reachable-state Rust-body guarantee is separate from the generic Lean composition through the official default model; arbitrary T, other std revisions and other state histories remain unproved. Separate generic Lean contracts cover actual public Hasher::write_length_prefix, write_u128 and write_i128 calls through compiler-inlined UFCS callers in std/no_std with debug assertions enabled/disabled. For every represented T under the original IsEnabled bound and every receiver state, debug length-prefix stores the usize-to-u64 cast and marks written when previously unwritten, or fails assertionFailure when already written. Without debug assertions it always overwrites the stored word. Both wide integer calls fail panic for every input and receiver state because their original standard defaults reach NoHashHasher::write. The separate900-check Kani evidence covers the ten original integer T instantiations: debug initial states and release default-or-once-written public states. Four further generic compiler-inlined caller contracts cover original Hasher::write_str in std/no_std with debug assertions enabled/disabled. For every represented T under IsEnabled, receiver state and string, including empty strings, the call fails panic: the original default first calls NoHashHasher::write on the string bytes, which unconditionally panics, so the trailing write_u8(0xff) is unreachable. There is no fixed string-length/content restriction.
