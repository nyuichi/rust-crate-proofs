Overview

For rand_xorshift 0.5.0, the Aeneas proof establishes the exact try_next_u32 word and state update for every four-u32 state, using three explicit std wrapping-operator models. With t=x XOR (x << 11), r=w XOR (w >> 19) XOR t XOR (t >> 8); the returned value is Ok(r) and state becomes (y,z,w,r), using 32-bit logical operations. A separate Lean theorem derives preservation of a nonzero state from this exact transition. Independently, Kani checks the unchanged from_seed body for every 16-byte seed: four little-endian u32 words are decoded, and the all-zero input is replaced by four 0x0BAD5EED words. The constructed state is nonzero. A second Kani harness checks that the original next_u32 body preserves every nonzero four-word state. These seed and preservation checks are supplementary Kani results, not an Aeneas seed-body claim. No original Rust source or manifest is changed. A further original-source Kani check covers every 16-byte seed, including the zero-seed fallback: from_seed followed by try_next_u64 returns the same little-endian low/high word composition as two try_next_u32 calls on an identical clone, and derived equality confirms every resulting state word agrees. This is a public-API relational guarantee over seed-constructed states, not an independent recurrence specification. Separate Kani also executes the original manual Debug formatter for every public from_seed input or seed_from_u64 input. With default formatting and a fixed64-byte writer it emits exactly "XorShiftRng {}" (13bytes), preserves the zero suffix and correct length; a writer rejecting the first write instead propagates fmt::Error with no bytes retained. A separate original try_fill_bytes relation is checked for every16-byte seed, every initial8-byte array and every requested prefix length0..8. Filling returns Ok, writes exactly the little-endian prefix from ceil(length/4) actual next32 calls, preserves the unused array suffix and yields an equal complete final generator state. Separate original from_rng/try_from_rng Kani relations cover concrete source protocols: every nonzero16-byte seed, optionally preceded by one all-zero block, produces the same complete state as public from_seed after exactly1or2 source fills. Fallible sources additionally propagate every u32 error payload after zero or one discarded zero block, preserving the expected call count even if the failing fill first writes arbitrary bytes. With the serde feature, a separate Kani check calls original Serialize for every public 16-byte seed through a fixed serializer: it emits the XorShiftRng struct with x/y/z/w u32 fields in order, matching little-endian seed words with the documented all-zero fallback, and leaves the RNG state unchanged. A failure at any of its ten serializer callback stages propagates the exact supplied u32 error and stops at that stage.

What is trusted

The Rust compiler, Charon/Aeneas translation, existing Aeneas scalar primitives, Lean kernel, and Kani/CBMC toolchains are trusted. Three executable std Wrapping<u32> models connect shift-left, shift-right, and xor to existing Aeneas primitives. Kani checks their Rust correspondence for all u32 operands and all 64-bit usize shift amounts; the relation between these Rust formulas and the Lean definitions remains an explicitly reviewed semantic bridge, not an in-Lean proof of the std bodies. No extra local axiom occurs in the public theorem's transitive dependencies. The seed and preservation harnesses embed the entire original Rust implementation as an unchanged prefix, appending safe observers in a std verification module. This preserves the implementation text but retains the documented verification-module and compiler/toolchain boundary. The separate Nonzero.lean proof uses the existing Aeneas exact transition theorem, not an assumed new seed theorem. This Serialize supplement trusts Kani/CBMC, the August Rust compiler and the exact rand_core 0.10.0 / serde 1.0.228 implementations; its finite callback serializer is the observed protocol, not an assumption about arbitrary serializers.

Technical limitations

The single Aeneas API mapping remains try_next_u32 on x86_64 without serde. from_seed and original nonzero-state preservation are independent Kani body checks. Aeneas extraction of the original seed body remains blocked by mutable zip iteration. Kani uses Rust nightly-2026-08-21 while Aeneas extraction uses nightly-2026-09-17; these are not mechanically linked proofs of one toolchain's std bodies. The three wrapping models retain their reviewed Rust-to-Lean bridge. The all-zero state is still covered by the exact step theorem; the initial-nonzero guarantee is for from_seed, not every unverified initialization or serialization path. General-state next_u64 correctness, fill_bytes, external-RNG initialization, formatting, inherited Rng wrappers and serde remain unverified. No period, distribution or cryptographic property is established. The separate try_next_u64 composition check covers only states constructed from_seed under default features and rand_core0.10.0. Arbitrary Rust-valid all-zero internal states, serde states, other histories, independent mathematical output formulas and a formal Rust-to-Lean bridge remain outside that check. This Debug result is limited to these public constructor images, default format flags and the fixed accepting-or-first-error writer; arbitrary Formatter states, partial-prefix errors, general writers and arbitrary private states are not established. The fill supplement covers only lengths0..8 in an8-byte allocation and states from public from_seed; arbitrary lengths/allocations, serde and arbitrary private states remain unproved. A separate0..64 attempt timed out and supplies no completed guarantee. This is an original public-API relation, not an independent recurrence proof or Rust-to-Lean equivalence. Source-based initialization is checked only for these concrete TryRng implementations and zero-or-one preliminary-zero protocol. It does not establish arbitrary source behavior, unbounded zero retries, unconditional termination, generic callback effects or serde behavior. Equality with from_seed is a relational result, not literal delegation or an independent seed-decoding specification. Serialize is checked only for the fixed callback protocol and states produced by public from_seed, not arbitrary Serializer implementations, arbitrary private states, Deserialize or other encodings. The separate Kani result adds no Aeneas machine claim.

Tool limitations

The author must review that the committed functional model matches the recorded Rust source, that the named theorem corresponds to the public API, and that the reported precondition matches the theorem. A checked theorem alone does not establish those links or the adequacy of the specification. The current adapter records the default Cargo configuration, with ordinary Lean module paths and a pinned official Git dependency. Other backends, custom Lake source directories, and local-path Aeneas dependencies are unsupported.
