Overview

For rand_xorshift 0.5.0, the Aeneas proof establishes the exact try_next_u32 word and state update for every four-u32 state, using three explicit std wrapping-operator models. With t=x XOR (x << 11), r=w XOR (w >> 19) XOR t XOR (t >> 8); the returned value is Ok(r) and state becomes (y,z,w,r), using 32-bit logical operations. A separate Lean theorem derives preservation of a nonzero state from this exact transition. Independently, Kani checks the unchanged from_seed body for every 16-byte seed: four little-endian u32 words are decoded, and the all-zero input is replaced by four 0x0BAD5EED words. The constructed state is nonzero. A second Kani harness checks that the original next_u32 body preserves every nonzero four-word state. These seed and preservation checks are supplementary Kani results, not an Aeneas seed-body claim. No original Rust source or manifest is changed.

What is trusted

The Rust compiler, Charon/Aeneas translation, existing Aeneas scalar primitives, Lean kernel, and Kani/CBMC toolchains are trusted. Three executable std Wrapping<u32> models connect shift-left, shift-right, and xor to existing Aeneas primitives. Kani checks their Rust correspondence for all u32 operands and all 64-bit usize shift amounts; the relation between these Rust formulas and the Lean definitions remains an explicitly reviewed semantic bridge, not an in-Lean proof of the std bodies. No extra local axiom occurs in the public theorem's transitive dependencies. The seed and preservation harnesses embed the entire original Rust implementation as an unchanged prefix, appending safe observers in a std verification module. This preserves the implementation text but retains the documented verification-module and compiler/toolchain boundary. The separate Nonzero.lean proof uses the existing Aeneas exact transition theorem, not an assumed new seed theorem.

Technical limitations

The single Aeneas API mapping remains try_next_u32 on x86_64 without serde. from_seed and original nonzero-state preservation are independent Kani body checks. Aeneas extraction of the original seed body remains blocked by mutable zip iteration. Kani uses Rust nightly-2026-08-21 while Aeneas extraction uses nightly-2026-09-17; these are not mechanically linked proofs of one toolchain's std bodies. The three wrapping models retain their reviewed Rust-to-Lean bridge. The all-zero state is still covered by the exact step theorem; the initial-nonzero guarantee is for from_seed, not every unverified initialization or serialization path. next_u64, fill_bytes, external-RNG initialization, formatting, inherited Rng wrappers and serde remain unverified. No period, distribution or cryptographic property is established.

Tool limitations

Lean backend only, requiring cargo-proofs 0.4.0 or later. The version identifies the official Aeneas Git revision pinned in lake-manifest.json (backends/lean); this revision uses Lean 4.35.0. The recorder checks committed Lean theorem declarations and permits only propext, Classical.choice, and Quot.sound as transitive axioms. It rejects sorryAx and custom axioms, including axiomatized external models. Charon/Aeneas extraction is not rerun. The author must review that the committed functional model matches the recorded Rust source, that the named theorem corresponds to the public API, and that the reported precondition matches the theorem. A checked theorem alone does not establish those links or the adequacy of the specification. The current adapter records the default Cargo configuration, with ordinary Lean module paths and a pinned official Git dependency. Other backends, custom Lake source directories, and local-path Aeneas dependencies are unsupported.
