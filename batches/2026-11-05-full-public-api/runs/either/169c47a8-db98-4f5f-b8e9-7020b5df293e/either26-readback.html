Overview

Twelve callback APIs compose a supplied mathematical callback contract with variant selection. is_left_and/right_and apply the callback only to the indicated variant and otherwise return false; is_left_or/right_or return true on the indicated variant and apply the callback to the other. map_left/right map only the named payload and preserve the other variant and payload. map_left_or/right_or return the mapped named payload or the supplied default. left_or_else/right_or_else preserve the named payload or compute it from the opposite payload. left_and_then/right_and_then return the selected callback-produced Either unchanged, or preserve the opposite variant and payload. Their normal-result proofs explicitly assume the supplied FnOnce dictionary returns the mathematical function value on every argument. Separate companion theorems show selected callback failure is propagated unchanged and non-selected branches preserve their result without any callback success premise. For either 1.19.0 with default features on x86_64, the following value-semantic guarantees exclude payload destructor effects; they do not establish Rust panic freedom for arbitrary Drop implementations. In that model, is_left/is_right identify the actual branch; left/right return the corresponding optional payload; left_or/right_or select that payload or the given default; flip swaps the branch and a separate composition theorem proves flipping twice returns the original value. left_and/right_and select the supplied value or preserve the opposite payload. factor_none moves the optional payload outside Either while retaining its tag. factor_first/factor_second move the common tuple component outside Either. as_ref preserves the variant and referenced value; as_mut preserves the initial view and its generated backward function writes a matching-variant replacement payload back to the original variant. The twenty-six original bodies terminate normally in the model for all well-typed values in their stated domains.
