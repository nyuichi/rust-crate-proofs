Overview

The new map_either/map_either_with contracts preserve the present variant while replacing its payload with the selected callback result; the context-aware form forwards the original context. Normal results require success only at that actual payload/context, and modeled failure/divergence propagate unchanged. inspect_left/right call the selected borrowed-value callback and return the original modeled self after success; on the other variant they return self without any callback premise. This self-retention is a property of the extracted shared-reference value model and does not certify unchanged observable Rust interior/global state under arbitrary callbacks. For either 1.19.0 with default features on x86_64, the thirty-nine named APIs have the following value-model contracts. either dispatches only to the callback for the present variant, passing exactly its payload; either_with additionally passes the original context as the first pair element. either_into dispatches that payload to the corresponding Into dictionary. Their main contracts preserve the selected computation's whole modeled Result without assuming success. Separate normal-value contracts need success only at the selected payload/context; failure and divergence helpers retain the same modeled outcome. The unused callback/conversion dictionary is unconstrained. Twelve earlier callback APIs compose a mathematical callback under their explicit normal-result premises for every callback argument, with selected failure propagated and nonselected results preserved. The real impl<T> IntoEither for T dictionary is linked to its original default, so into_either_with requires only normal predicate behavior at the actual borrowed input. Predicates/projections identify and retain the exact variant and optional payload; flip swaps it and flipping twice reconstructs the original. Eager selection preserves the indicated payload or supplied alternative. Optional and tuple factoring preserve tags and exact components. as_ref preserves the borrowed view; as_mut's backward function writes a matching-variant replacement payload back. The original handwritten conversions map Result Ok to Right and Err to Left, with exact payloads, and reverse those mappings; both roundtrips reconstruct every variant. left_or_default/right_or_default preserve the matching payload without a Default premise and otherwise delegate the Default computation's entire modeled outcome. Normal fallback values, modeled failure and divergence have separate explicit premises. The earlier thirty APIs return normally in this model under their stated conditions; the Default fallback pair and the three dispatch APIs retain abstract selected-computation outcomes. These are value-semantic guarantees with the destructor and callback boundaries stated below.
