# Verification guarantees

For rand_xoshiro 0.8.1, the unchanged native word-generating method of each of its fifteen generators returns Ok of the specified output scrambler and performs the exact documented word-state transition. Coverage includes SplitMix64, both xoroshiro64 variants, all three xoroshiro128 variants, and all three variants of each xoshiro128, xoshiro256 and xoshiro512 family. For 32-bit-word engines the native method is try_next_u32; for 64-bit-word engines it is try_next_u64. SplitMix64::try_next_u32 is also proved independently, including its distinct Mix4 output formula, for sixteen proved API bodies. Each theorem covers arbitrary internal words, including all-zero states, and establishes normal termination in the Aeneas model. Array-state representation theorems establish that the four-word and eight-word inputs cover every valid fixed-length engine state. Exact output formulas and resulting fields are defined independently of the generated Rust body in the output*/next* specifications. The selected original bodies have byte-identical official Aeneas translations under the default and serde feature configurations, so these body guarantees apply to both configurations; this does not verify the serde trait implementations. Nine further 32-bit APIs are verified through exact forwarding selectors whose calls to the unchanged original API are inlined by the Rust compiler: all three xoroshiro128, all three xoshiro256 and all three xoshiro512 variants. These establish the same state transition as their 64-bit method, with low 32 output bits for xoroshiro128++ and xoroshiro128**, and high 32 bits for the other seven variants. This yields twenty-five API guarantees: sixteen direct original-body proofs and nine compiler-inlined original-API call proofs. The selector source, typed receiver/return correspondence, target, original method inline scopes and absence of unknown externals are guarded. Default and serde selected programs are byte-identical. Four additional direct body proofs cover Seed512: Default initializes all 64 bytes to zero; AsRef exposes exactly the stored bytes; AsMut exposes those bytes and writes back every legal 64-byte replacement unchanged; iter initializes the standard slice-iterator model over those same bytes at position zero. There are twenty direct body proofs and nine compiler-inlined original-API call proofs, for twenty-nine registered APIs. SplitMix64::state is additionally proved to return exactly the eight little-endian bytes of its complete internal u64 state, for every state including zero. Thirty registered APIs comprise twenty-one direct bodies and nine compiler-inlined calls. All fifteen generators’ state methods are now covered: each returns the complete fixed-length little-endian bytes of every stored unsigned word in field order, for arbitrary internal word patterns including all-zero. Fourteen additional serializers bring the registered total to forty-four: thirty-five direct original bodies and nine compiler-inlined calls. The eight-word serializers also have a decreasing-measure proof that the original enumerate loop terminates after visiting each word. These are serialization results, not serde trait implementation proofs.

## Trust boundary

The Rust compiler, official Charon/Aeneas translation, official Aeneas array/scalar models and Lean kernel are trusted. No source adaptations or local helper axioms are used. Eleven newly covered two/four-word state serializers use a custom executable size_of model with explicit layout evidence only for U32=4 and U64=8 bytes. The original generated Types/Funs remain byte-for-byte official outputs. The Lean evidence class is open; this packet supplies exactly these two primitive instances and guards all eleven generated calls and their frozen elaborated instance bindings. Bool and array types have no supplied evidence and are rejected. This is not a universal type-layout theorem. The three eight-word serializers do not call size_of. Archived independent Kani layout checks confirm the Rust u32/u64 sizes under nightly-2026-08-21; Aeneas extraction uses nightly-2026-09-17. ABI agreement across those compilers and correspondence of Rust layout to the Lean evidence remains an explicit, non-mechanical model bridge. All API and supplementary direct/selector theorems have dependency audits permitting only propext, Classical.choice and Quot.sound. Standard shifts, rotations, wrapping arithmetic and array operations use official Aeneas models, rather than body proofs of Rust std implementations. The nine selector proofs additionally rely on Rust compiler inlining of the exact original API call; retained MIR scopes identify each original TryRng method and Rng wrapper. The selector does not replace or assume an opaque original API: generated native callees are body-proved and no unknown external definitions remain. Seed512 byte-view and iterator initialization proofs use the official array-to-slice and slice-iterator models. The mutable reference model specifies write-back of the fixed-length referent; resizing that referent is not a legal returned-slice operation in safe Rust.

## Remaining work

Forty-four registered APIs are covered: thirty-five direct original bodies and nine compiler-inlined calls, under default or serde features on x86_64-unknown-linux-gnu. The eleven two/four-word state serialization guarantees depend on the explicit primitive layout model and its documented compiler/model boundary. The five 32-bit-engine try_next_u64 compositions, buffer filling, seed construction, jump/long_jump, Seed512 formatting and external iterator operations, manual Debug, serde and inherited/default/external blanket methods remain outside these registered Aeneas claims. Separate Kani seed/state/composition evidence is supplementary and not an Aeneas claim. All-zero states are included in the formulas; ordinary seed reachability, period, distribution, independence and cryptographic security are not established. Other targets and untested dependency feature combinations are not covered.
