# Original state byte serialization

Fifteen ordinary Kani harnesses call each original rand_xoshiro 0.8.1 state method on every complete internal word state. Each returned byte is checked against independent little-endian shift/mask extraction. For the three xoshiro512 variants the original result is Seed512 and its public byte field is checked. The output has its original fixed length. The generator state contains only unsigned scalar words/fixed arrays, so every input bit pattern is valid Rust data, including zero. These observers intentionally cover internal states beyond the ordinary seed constructors' reachable subset; no claim says all-zero generators can be produced through the usual public seeds. Serialization itself does not need the generator's intended nonzero algorithmic invariant.

The measurement copy retains every original Rust file as an entire byte prefix, appending only cfg(kani) private-state constructors and a private harness module declaration. Every original method is untouched. check-source.py validates all original Rust prefixes and Cargo manifest against upstream.crate, exact observer suffixes and harnesses without assumptions/stubs. Reference bytes use shifts/masks, not the original state method or standard to_le_bytes. The input size is the API's actual fixed-size state rather than an artificial testing bound. Standard safety/unwinding checks remain enabled.

Only completed per-configuration results count. probe-512.log independently establishes Xoshiro512Plus on every 512-bit state (1205 checks); it does not establish all fifteen variants. Both complete batches succeeded: fifteen harnesses under default and fifteen under serde. See results.json for each API/configuration check count. These checks are proof obligations, not sampled test cases. Reproduce ./verify-kani.bash, with a 900-second ceiling for each feature configuration. Kani 0.68.0 / CBMC 6.11.0 uses nightly-2026-08-21, distinct from Aeneas. These are separate tool guarantees and ordinary harnesses, not machine-registered Aeneas/API-bound contract claims. No seed restoration, roundtrip for zero-remapped seeds, generator period, statistical quality, or serde implementation is established by serialization alone.
