# Original fixed-size seed initialization

This supplement checks the original rand_xoshiro 0.8.1 `SeedableRng::from_seed` body for each of its fifteen generators. The input is every value of the API's complete fixed-size seed: 8, 16, 32 or 64 bytes. SplitMix64 accepts every eight-byte seed directly. For the other fourteen generators, a nonzero seed is decoded directly and an all-zero seed uses the corresponding prefix of the original published 64-byte fallback sequence. Each resulting private word is checked against independent little-endian byte concatenation. This is exact initialization, not a claim about randomness, stream period, nonzero-state preservation under subsequent generation, seed_from_u64 for the fourteen non-SplitMix engines, or serialization methods.

All fifteen original seed body contracts succeeded independently under default and serde (15 harnesses per configuration). See default-kani.log, serde-kani.log and results.json for per-API check counts. These are proof checks, not sampled test cases. probe-512.log is retained as an earlier independent largest-input success. Failed/incomplete attempts are never counted.

The production crate's Rust files and Cargo manifest are unchanged. The measurement copy retains every original Rust file's complete byte prefix, appending only cfg(kani) read-only private-word observers and a harness module declaration. No original method is modified, replaced, annotated or stubbed. check-source.py verifies these exact suffixes and unchanged other Rust/Cargo files against upstream.crate before running. Constructor observers are not needed: the harness calls the real original from_seed. References use scalar byte concatenation and an explicit fallback literal, not from_seed/read_words calls. Every returned word is asserted, with no assumptions or excluded seeds. Standard Kani safety and unwinding checks remain enabled. Static seed sizes are the API's actual domain, not a user-selected artificial bound.

Kani 0.68.0 / CBMC 6.11.0 uses nightly-2026-08-21 on x86_64, separately from the Aeneas toolchain. No formal cross-tool link is asserted. Original source with the same default/serde configuration is checked separately. These ordinary #[kani::proof] harnesses are supplementary evidence: the current cargo-proofs Kani registration expects API-bound proof_for_contract and cannot register these ordinary harnesses as machine claims without changing the original API. No Aeneas completion is inferred from this tool.

Reproduce using ./verify-kani.bash; each feature configuration has a 900-second execution ceiling. All logs, original archive, observer provenance, harnesses and API bindings are retained. prepare.py recreates the measurement source from the archive. It must not be run while verification is active.
