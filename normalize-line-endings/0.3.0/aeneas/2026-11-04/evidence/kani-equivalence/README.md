# Original/adapted next-body equivalence under coupled callback traces

Kani 0.68.0 checks the original and adapted Rust `Normalized::next` bodies on the same symbolic callback trace. For every initial `prev_was_cr`, every pair of valid `Option<char>` results, and every initial/post-callback `u64` observable state, both bodies return the same `Option<char>`, set the same next `prev_was_cr`, make the same number of callback invocations, and leave the same complete `ScriptedIterator` value. Each body makes one or two callback calls. Results may be `None` followed by `Some`; no fused-iterator condition is imposed on this local comparison.

The inputs are symbolic, not a finite list of examples. Two callback slots suffice for one invocation because each source body calls its underlying iterator at most twice. This two-reply bound is not a bound on input string length. The original source has no loop. This is a one-step relational proof over the supplied callback model; it does not independently quantify over every Rust iterator implementation or establish the entire release's behavior over repeated calls. The Lean proof separately covers arbitrary finite lengths for the adapted source under its finite-list iterator model.

Callback invocations in this harness return normally. Their internals, panic or divergence, arbitrary external side effects, and arbitrary state representations are outside this check. The model couples the two executions to identical return values and observable `u64` state updates. It does not treat a callback returning `None` as permanent exhaustion. The harness contains a panic if either implementation requests a third callback, and Kani proves that path unreachable.

`prepare.py` reads the complete actual files `../../src/lib.rs` and `../../translation-source/src/lib.rs`. It writes each file unchanged as the byte-identical prefix of a separate module and appends only a verification observer that accesses private fields and calls the source's actual `next` method. No implementation body is manually copied into the harness. `source-manifest.json` records both source and generated hashes. The source difference remains exactly the three character-pattern-to-equality-guard edits recorded in `../char-pattern-to-guard.patch`.

Run `./verify.bash` with Kani 0.68.0 and its exact Rust toolchain, `nightly-2026-08-21`, installed. Set `KANI_HOME` to the extracted official verifier bundle if it is not `/workspace/kani-tools/kani-0.68.0`. The recorded run used CBMC 6.11.0 on x86_64 Linux. `result.log` records one successful harness and zero failed checks (314 checks, two unreachable). Compiler warnings mention unsupported formatting/caller-location constructs; the verifier completed successfully, so no unsupported construct was reachable in this harness.
