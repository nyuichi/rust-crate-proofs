# Exact range behavior — research candidate, not published

This checkpoint extends the separately frozen all-input partial-correctness packet without changing the separately frozen packet. Its Rust source, generated functions/types and existing proof text are preserved in this candidate. This candidate maps the same two public method keys to strengthened ExactRange contracts; it is not published yet. The installed official tools and libraries were not changed; no provider or standard model was added.

For any represented raw generator state and any valid range, define width=end-start and the canonical threshold `(2^b-width)%width`, where b is32 or64. Candidate0 consumes the first actual PCG word and advances the generator once. Each next candidate consumes the next actual PCG word and advances it once more. Candidate state, wide product and low word are explicitly defined by `ActualLoop32.next`/`ActualLoop64.next`; low uses the same mask and narrowing cast as the original body. No independent random-word oracle or state-reachability assumption is introduced.

`PublicTrace32.public_first_accept` and `PublicTrace64.public_first_accept` prove that if candidate n is accepted and every earlier candidate rejected, the complete original public method terminates normally. The returned sample has mathematical value `candidate_n.product.val / 2^b + start.val`, and the returned generator is exactly candidate_n.state, which is the state after consuming n+1 words. The supplied typed width is required to equal the mathematical range difference; all other arithmetic, canonical threshold calculation and its strict bound below width are proved. Acceptance is the explicit low-word comparison against this canonical threshold.

`public_all_rejected` proves for each type that if every candidate is rejected, the complete original method diverges. `TraceAudit.first_or_none` supplies the classical exhaustive division into a least accepted index or rejection at every index. Invalid ranges retain the original debug-assertion failure contracts. Therefore these cases describe all inputs in the extracted debug configuration. This logical case split is not an executable algorithm deciding whether sampling will terminate.

The existence of an accepted index is a condition, not a guarantee for all states or ranges. No unconditional termination, expected runtime, PCG period, distribution uniformity, constructor reachability of every restored state, panic/unwinding behavior or different extraction configuration is established. The already proved from_state((0,0)) followed by0..3 divergence remains consistent with this characterization.

The32-bit original loop uses wrapping64-bit multiplication; the64-bit original loop uses checked128-bit multiplication. The latter is connected to the candidate representation only after proving the full product fits128bits for every typed word and positive width. Both initial checked multiplications are treated similarly. This is a proved value equality, not replacement of the original checked operation with an unchecked stub.

The generic finite/infinite trace lemmas, original loop-body equations, public prefix/fast-path/loop/suffix connections, and both-width simultaneous import have passed the Lean kernel. The audits use only propext, Classical.choice and Quot.sound. Each new job was independently stopped at30seconds or4500MiB RSS; successful jobs took a few seconds with peaks about3.66GiB. No general translator-correctness claim is made.
