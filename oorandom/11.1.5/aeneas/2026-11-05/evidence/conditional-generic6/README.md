# Oorandom conditional conversion bodies: six API families

For Rand32 and Rand64, Into<U> returns exactly the supplied From callback result; TryInto<U> forwards the complete supplied TryFrom result, including its Ok/Err payload. The blanket TryFrom<U> calls U's Into callback and wraps a normal return in Ok. Its Rust error type is uninhabited (`Infallible = !` in the pinned compiler), so it cannot normally return Err. Modeled callback failure and divergence propagate. These bodies neither validate the input nor independently advance the RNG.

These are conditional generic-family contracts, not six selected concrete target-type examples. The actual Rust bounds remain required: U:From<Rand> for Into, U:TryFrom<Rand> for TryInto, and U:Into<Rand> for TryFrom. Associated Error for TryInto is the selected U::TryFrom<Rand>::Error; the lifted model parameter is not a new unconstrained Rust source generic. The theorems quantify the modeled type and supplied dictionary and cover every valid modeled owner/input. They do not prove arbitrary user conversion correctness, termination, Rust Drop/unwind details, global/heap effects, panic locations, physical aliasing/layout, resource availability or const evaluation. Rust trait availability/coherence is not asserted for arbitrary U.

The six primary mappings are in `api-bindings6.json`. They target the original core implementations, not the extraction driver's wrapper methods. TryFrom's two owner specializations use the direct body generated by unchanged official Aeneas. Into/TryInto's four owner specializations use the direct bodies generated by the separate finite export-only experiment below. Their exact delegation agrees with the existing registered Std models by additional kernel-checked theorems. The earlier `_model` lemmas remain supplementary and are not the primary four API contracts.

Binder substitution is single-pass with separate source and caller scopes. The original Oorandom11.1.5 archive is extracted unchanged under `source/oorandom`; the original public Oorandom.lean model is byte unchanged. No Rust or LLBC content was hand-adapted to make the proof work. Negative guard mutations run only in memory and are not proof/translator inputs.

The experimental generator has four source changes, default off: select exactly the original generic core Into/TryInto external transparent bodies, allow their already computed Pure bodies through the backend's builtin-export suppression, and omit only their duplicate rust_fun registrations.
