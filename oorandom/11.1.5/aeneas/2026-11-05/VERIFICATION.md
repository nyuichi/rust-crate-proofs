# Exact integer generation, seed initialization and state restoration in Rand32 and Rand64

For oorandom 11.1.5, twelve unchanged APIs have exact value/state proofs: new, new_inc, state, from_state, the unsigned output method and the signed output method for both Rand32 and Rand64. For arbitrary seed and increment input, new_inc normalizes the stream to ((increment << 1) OR 1), starts at zero, performs one PCG state update, adds the seed modulo the state width, then performs a second PCG state update. new uses the published DEFAULT_INC. state returns the exact current state and increment, and from_state restores those values unchanged; two additional composition theorems establish save/restore identity. Unsigned generation returns the exact PCG-XSH-RR output permutation of the old state and advances to multiplier*state+increment modulo 2^64 or 2^128. Signed generation preserves that updated state and reinterprets the unsigned result bits as i32 or i64. Each covered call terminates normally in the Aeneas model for every scalar input, including zero states and even restored increments.

The proof covers twelve integer/state APIs on x86_64-unknown-linux-gnu with the original default configuration. rand_float and rand_range for both generators remain unproved, as do non-excluded inherited/default and external blanket methods. The save/restore composition theorem establishes pure state identity; no arbitrary user callback or destructor behavior is modeled. No period, statistical distribution, independence or cryptographic guarantee is established. Other targets were not checked.

The Rust compiler, official Charon/Aeneas translation, official Aeneas scalar models and Lean kernel are trusted. No custom external models or local trusted helper contracts are used. All fourteen public and supplementary theorem dependency audits permit only propext, Classical.choice and Quot.sound. Standard-library wrapping, casts, shifts and rotations use official Aeneas models, rather than body proofs of Rust std implementations.

PCG multipliers: 6364136223846793005 (64-bit state), 47026247687942121848144207491837523525 (128-bit state). The output permutation is lowW(((s >> a) XOR s) >> b), rotated right by low32(s >> c): W/a/b/c are 32/18/27/59 and 64/29/58/122. All right shifts are logical.
