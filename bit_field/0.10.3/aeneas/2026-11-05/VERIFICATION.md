# Exact bit reading and bit setting for u8

For bit_field 0.10.3, get_bit returns the requested bit for every byte and index 0 through 7. set_bit produces x OR (1 << bit) for true and x AND NOT (1 << bit) for false, with 8-bit operations, and returns a mutable reference to that updated byte. Its translated backward function is the identity: a later write through the returned reference updates the original byte to that value. Both unchanged method bodies terminate normally in the model on these inputs. One manual executable size_of::<u8>() = 1 model is supplied, with extraction guards restricting its use to the sole u8 instantiation. Kani independently checks the original Rust methods against the reference formulas and returned-reference behavior, and checks the u8 layout value.

Only the u8 implementations of get_bit and set_bit at valid indices 0 through 7 are covered, on x86_64-unknown-linux-gnu with default features and debug overflow checks. Invalid indices, other integer types, get_bits/set_bits, BitArray methods, other targets and release behavior are not verified. No generic size_of property is established. Kani uses a different Rust nightly from Aeneas extraction; its layout and body checks do not prove the extraction toolchain itself.

The Rust compiler, official Charon/Aeneas translation, official scalar models, Lean kernel, and Kani/CBMC are trusted. One manual executable external model supplies size_of::<u8>() = 1. Its generic Lean signature comes from extraction but does not model arbitrary types: guards inspect all serialized LLBC functions and generated Lean modules and reject any non-u8 size_of call or additional translated methods. Kani checks the Rust u8 layout value; its correspondence to the Lean model is a reviewed bridge, not an in-Lean proof of Rust standard-library layout. Public theorems use only propext, Classical.choice and Quot.sound.

Reproduce with `./verify-all.bash` and `./verify-kani.bash`. The original archive is in evidence/upstream.crate. Official generated Types/Funs/template/manifest are retained unchanged. The model provider checks every serialized LLBC function before supplying its manual model. Kani depends directly on the unchanged original crate, not a copied implementation.
