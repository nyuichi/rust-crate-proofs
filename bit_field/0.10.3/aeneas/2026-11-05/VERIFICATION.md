Exact single-bit reads, updates and out-of-range panics for all integer types

For bit_field 0.10.3, the unchanged get_bit and set_bit bodies are verified for all twelve signed and unsigned integer types on x86_64. Every in-range index reads the requested bit or sets/clears exactly that bit; other bits are preserved. set_bit returns a mutable reference to the updated integer, and subsequent writes through that reference update the original value. Every out-of-range index fails at the explicit assertion. All twelve BIT_LENGTH values equal the integer widths. Original Rust source and Cargo.toml are unchanged. The Lean proofs use twelve explicit, separately monomorphized size_of integer layout models; Kani independently checks the original methods, returned-reference behavior and layout values for arbitrary valid inputs.

The official Charon/Aeneas translation and scalar models, Rust compiler, Lean kernel, and Kani/CBMC are trusted. Twelve executable models supply size_of for the twelve integer types, with x86_64 byte sizes 1,2,4,8,16 and pointer size 8. No model is provided for arbitrary other Rust types. Kani layout/formula checks and Lean bitvector models are a reviewed semantic bridge, not mechanically connected proofs of Rust standard-library layout in Lean. The pointer-sized theorems explicitly assume System.Platform.numBits=64. All mapped transitive axiom audits permit only propext, Classical.choice and Quot.sound.

Only get_bit, set_bit and the associated primitive BIT_LENGTH values are established. The get_bits/set_bits range methods, generic BitArray slice methods, downstream trait implementations, other targets and release extraction remain unproved. The out-of-range result describes the translated explicit assertion failure, not panic text or unwinding side effects. Kani checks valid-index original method behavior and layout; Lean separately proves invalid-index assertion failure. Kani and Aeneas use different Rust nightly versions. This is partial crate coverage, not a proof of all public APIs.
