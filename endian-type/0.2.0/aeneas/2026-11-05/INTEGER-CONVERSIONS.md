# Integer conversion behavior in endian-type 0.2.0

For all 60 integer From implementations of endian-type 0.2.0, the unchanged bodies return the exact identity or byte-reversed stored word under explicitly supplied x86_64 little-endian scalar-operation models. LittleEndian construction and conversion to an integer preserve the word; BigEndian construction and conversion to an integer reverse its bytes. Conversion between the wrappers reverses the stored word. Coverage includes every bit pattern of u16/u32/u64/u128/usize and i16/i32/i64/i128/isize. Pointer-sized Lean theorems explicitly require System.Platform.numBits = 64.

Fifty executable standard-library operation models compose official Aeneas byte primitives. Signed words use their same-width two's-complement bit patterns. Each model is proved to implement a separate byte-reversal or identity specification; all 60 original function bodies are proved against those specifications. Guards fix the 60 original functions, 50 monomorphic external signatures, and every original body's exact scalar-operation call. A verification driver reaches the actual original dependency functions without modifying crate sources. Compiler-owned path remapping makes their source spans reproducible.

Kani independently checks all ten Rust integer types against explicit reversed-byte references: ten symbolic harnesses and 216 successful checks. Rust byte formulas and the official Lean primitives are connected by review, not a mechanically checked Rust-to-Lean theorem. Kani uses a different Rust nightly from extraction. The compiler, Charon/Aeneas, official byte models, Lean kernel and Kani/CBMC remain trusted. All 110 model/body theorems have only propext, Classical.choice and Quot.sound as transitive axioms.

This result does not cover the 46 byte/slice APIs, their memory-safety obligations, other platforms, or other trait/blanket operations. It supplies conditional original-body conversion guarantees and does not establish complete crate verification.
