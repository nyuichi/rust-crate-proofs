## Control interpretations

- **missing-registration:** the callback passed to `shallow_clone_arc_checked` omits `State::on_register`. Two `vc_shallow_clone_arc_checked` leaves are null: the final `shot_store` condition and a returned-child/cursor invariant.
- **omit-peer:** the `bytes_detached_child_terminal_drop(peer, ...)` call is removed while peer-receipt assertions remain. The null `vc_finite_shared_scope` task concerns resolving the popped peer’s data and Root/Child proof.
- **skip-drain:** the entire `owners.pop()` loop and its invariants/drop calls are deleted while the empty-owner/singleton-observation assertion remains. The null task prints that conjunction as the postcondition.
- **forget-peer:** the normal child terminal-drop call is replaced with `core::mem::forget(peer)` while the peer-receipt assertions remain. Its null task is again the popped peer-data / Root-or-Child resolution condition.
- **nonempty-vec-drop:** the drain loop and emptiness assertion are deleted but the empty-Vec terminal effect remains. The two printed goals require the owners Vec view to be empty and the returned completion to be reclaimed. This tests proof sensitivity to the empty-vector precondition in the selected client path; it is not evidence about Rust Vec’s native storage destruction.
- **omit-root-recovery-publication:** `State::on_release` changes `state.recovery = Some(sealed)` to `let _=sealed` in the singleton-root branch. The two null goals require a non-None root recovery option and a valid final protocol state.
- **missing-acquire:** one `negative_missing_acquire` feature disables the guarded Acquire-callback registration in the retained public_shared and AP promotion bodies. `release_core` and `shared_drop_checked` each have an `acquired_Payload` null goal. This is one feature mutation with effects in two bodies, not two independent coverage results.
- **missing-payload-free:** one feature replaces actual `physical_projection::deallocate(...)` with a conjured `FreeReceipt`; both `promotion/free_recovered` and `public_shared/free_recovered` have a null `vc_free_recovered` whose printed goal is `not inv_Atomic_usize(...)`. This is a single feature-level sensitivity result. The conjured receipt is not a demonstrated real deallocation or direct payload-free receipt theorem.
- **missing-control-free:** one feature replaces the typed control-block deallocator with a conjured `TypedFreeReceipt`. Each `free_recovered` VC is null on the physical buffer `FreeReceipt` condition (namespace, address, size, alignment, allocated); neither null is a `TypedFreeReceipt` condition. This is one feature-level sensitivity result and does not establish control-block deallocation or a direct receipt.

A null leaf means the selected VC was not discharged; it is not an SMT counterexample and is not a direct runtime observation. These controls show proof sensitivity to source perturbations, not independent runtime laws. For omission/forget controls, do not interpret the result as a standalone destructor theorem. `omit-root-recovery-publication` is a source-control capture (`source_control=omit_root_recovery_publication`); its archive itself retains the mutation even if the live source is restored later.

Each archived Coma, proof JSON, printed task, printer stderr, tree path, and hash is saved under `ap-semantic-null-tasks/<capture>/`. The printer exited zero and emitted nonempty tasks. Captured stderr has Why3 plugin-load / axiom warnings, which did not prevent task extraction. The proof archives remain diagnostic and do not establish independent source correspondence or final gate admission.
