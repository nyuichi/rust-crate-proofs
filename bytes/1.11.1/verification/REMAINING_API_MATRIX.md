# Remaining public API verification matrix

Snapshot reviewed: bytes 1.11.1 at the 2026-10-05 checkpoint. This is a source inventory and task map, not a completion percentage. It distinguishes exact extracted API bodies from helper-only results, native tests, and the model-only `src/verification.rs`.

## Evidence rules and inventory caveat

The default-std rustdoc surface is recorded in `artifacts/surface-manifest.json` (`std;x86_64-unknown-linux-gnu`, 997 compiler items). `PUBLIC_API_COVERAGE.csv` is useful for enumerating methods, but its rows for the public `Bytes`, `BytesMut`, `Buf`, and `BufMut` items still say `not_started` and have empty contract/artifact fields, including rows whose source participates in newer isolated gates. Use the exact extraction manifests and current `STATUS.md` to determine what a gate actually proves. Do not turn a helper row into an API claim.

`src/verification.rs` is an intentionally separate logical state-machine model. It is not the upstream public implementation and none of its methods count as actual public API body evidence. Similarly, the comparison helpers, arithmetic/cursor/codec helpers, storage helpers, native tests, and standard `Bytes` docs do not by themselves prove a public caller or trait dispatch.

## Public `Buf` methods

The current strongest API-shaped result is the exact concrete `impl Buf for &[u8]` gate: `slice-buf-overrides/complete-positive` mechanically extracts 40 actual method bodies—19 checked integer reads, the 19 normal-return getters, and `remaining`/`chunk`—with exact value/suffix or unchanged-input error contracts. It includes fixed widths through 128 bits in both endian orders and unsigned variable widths 0..=8. Its inverse-checked extraction preserves concrete slice receivers. It does **not** prove trait dispatch/refinement for arbitrary `B: Buf`, or `Bytes`/`BytesMut` implementations.

The public trait declarations have prose implementer laws but no Creusot contracts tying `remaining`, `chunk`, `advance`, initialized writes, and cursor movement together. The `generic-buf-predicates` probe proves 10 positive obligations and intentionally rejects its inverted `Buf` predicate in three proof files. It mechanically extracts both exact default predicate bodies and the selected `&[u8]`/`&mut [u8]` remaining bodies, then checks them through local `BufPredicateSurface` and `BufMutPredicateSurface` interfaces with metadata getter contracts. Those local interfaces are narrower than the public traits: this is not proof of original-trait dispatch, arbitrary implementors, or a safe public API law.

Do not integrate the predicate relation as a global trusted law. `Buf` and `BufMut` are open to downstream implementations, and contracts on their actual default methods would impose a law on those implementations. A source-level integration should add the contract to the real trait method only if the verifier can establish it from actual trait dispatch for all admitted implementations or the API explicitly adopts and documents that implementer obligation. Otherwise, retain a sealed/private proof interface and keep the claim restricted to implementations whose metadata refinement is proved. The probe uses no trusted attribute and does not establish a public-trait contract.

## Safe bounded next targets

1. **Public-trait integration for the predicate pair.** The isolated experiment is complete: the two exact defaults and selected slice metadata refinements pass through narrowed local traits. The next integration change must decide and verify how a postcondition on an open public trait is justified for downstream implementations. Preserve the boundary between the probe and full `Buf`/`BufMut` dispatch; do not carry its local metadata contracts over as a trusted universal trait law.
2. **The first stateful generic `Buf` method after a sound trait contract.** Specify actual trait laws: `remaining` is nonnegative; `chunk().len() <= remaining`; `remaining > 0` implies a nonempty chunk; `advance(n)` requires `n <= remaining` and drops exactly the first `n` bytes from the logical unread sequence. Then target default `try_get_u8`: success returns the old first unread byte and advances one; failure reports `{requested: 1, available: old_remaining}` and preserves the cursor. The concrete slice extraction is useful implementation evidence but must remain distinct from the generic contract.
3. **Comparison integration beyond the restricted `BytesMut` probe.** The handle-comparison gate proves exact extracted `BytesMut` self/slice trait bodies against the added `Seq<Int>` model under its checked unique-initialized invariant. It does not prove the production `Bytes` comparison traits or whole-crate dispatch, and its generated purity annotations extend the immutable physical-read path. Keep the cross-type `Vec<u8>` result native-only. The passed-table refactor removed the earlier vtable recursion cycles; current full-crate translation still has trait/purity errors. The historical `PartialOrd` normalization ICE is not the current blocker.
4. **Generic iterator integration after `Buf` laws.** The concrete gate proves `IntoIter<&[u8]>` suffix advancement, the returned head byte, `size_hint`, and exact length using exact extracted bodies. Generic `IntoIter<T: Buf>` still needs nonempty-chunk and one-byte-advance facts plus an `IteratorSpec` for arbitrary implementors. The standard iterator `next` spec is conditional on `IteratorSpec`, while `size_hint` has no bundled contract. Avoid claiming generic iterator correctness from this concrete specialization or ordinary iterator tests.
5. **Advanced unique-invariant integration.** The retained exact-source attempt still fails at `advance_unchecked`'s current-state invariant (27/28); predicate simplification and localizing the next descriptor did not resolve it, and flattened invariant regressed spare access. A new `advanced-transactional` probe is now testing a different structure: replace `self` with the canonical valid empty, move every affine field into an invariant-free raw transition carrier, update pointer/offset/length/capacity there, then construct one fresh strong-valid handle. Its evidence is separate from the failed direct-body gate and will establish only the transition shape it proves.

## Feature gates and panic status

The only rustdoc surface manifest here is default `std` on x86_64. Ordinary `no-default-features` compilation passes at the recorded checkpoints, but that is not a no-std API proof inventory. `Buf::chunks_vectored`, `Buf::reader`, `BufMut::writer`, and `Buf for std::io::Cursor<T>` are `std`-gated; `reader`/`writer` are also cfg-disabled for Creusot. `Buf::take`, `Buf::chain`, and `BufMut::chain_mut` are similarly cfg-disabled for Creusot. The proof configuration therefore does not translate the same complete public trait surface for those methods.

Normal-return preconditions intentionally make panic helpers unreachable in the slice-reader gate. That gate explicitly does not prove panic messages, panic behavior, or unwind cleanup. Public bounds panics (`Bytes` range/split, `BytesMut` split/set_len/reserve paths, `Buf` advance/getters, and `BufMut` capacity checks), allocation failure, and automatic destructor effects have no general proof coverage. Native `#[should_panic]` tests are behavioral checks, not panic proofs.
