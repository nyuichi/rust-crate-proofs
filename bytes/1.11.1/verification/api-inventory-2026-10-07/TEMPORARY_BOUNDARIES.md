# Original bytes 1.11.1: temporary-boundary strategy

Read-only architecture review, 2026-10-07. The renewed target is the original crate/API, including its Data/Shared/vtable representation and automatic destruction. Earlier route-1 decision documents describe a superseded target; their counterexamples and tool observations remain relevant. No source, verifier, contract or trust annotation was changed for this review.

## What can be localized, and what remains an obligation

| Boundary | A bounded temporary treatment preserving native bodies | What its removal must establish |
|---|---|---|
| Raw allocation, pointer/slice representation, layout casts | Keep explicit generic primitive contracts with identity, initialized range, exclusivity and final-borrow frames. These already form a reviewable physical TCB. | Adequacy against Rust allocation/provenance semantics; never infer access authority from numeric address/capacity equality. |
| Vtable calls and static/function-pointer materialization | A proof-only dispatch boundary may carry the exact callback pre/postcondition and relation to the actual table. A trusted caller-facing contract can defer body translation. Native code need not become Vec-backed. | Function-pointer/static translation plus table construction/callback refinement for every actual representation, including Owned<T>. A finite tag handles dispatch only; it does not prove ownership. Whole-crate static translation may require an additional explicit proof projection. |
| Bytes::clone(&self) | A temporary contract can promise preserved bytes, a valid new registered handle and preserved original handle, scoped to the existing representation invariant. | Real shared-reference interior ghost/resource update coupled to the actual atomic increment, promotion/CAS cases and publication. This is currently an assumed protocol obligation, not merely a syntax hole or a demonstrated few-line future replacement. Do not duplicate affine allocation ownership as its specification. |
| Send/Sync validator markers | Tool-required trusted marker syntax can be listed as a separate audited obligation, without changing native layout/API. | An actual transferable/shared resource invariant for Bytes/BytesMut and all owner variants. Marker acceptance is not a concurrency proof. |
| Immutable Deref/AsRef | A precise read-only borrow boundary with initialized-view and lifetime authority can isolate raw representation/tool gaps. | The invariant must provide real read authority in every default representation. An immutable check(ghost) classification must be supported by erasure/purity, not just clear a trait error. |
| Mutable DerefMut/AsMut/chunk_mut | Model a typed exclusive borrow with initialized/uninitialized slots, final writeback and outside-range frame; retain original public methods. | A sound program/ghost effect treatment and actual mutable authority. D01's known-erasure-unsound mutable raw B4 annotation cannot be temporarily assumed safe. |
| Automatic Drop | A destructor body can have a temporary contract, but this alone has no caller effect when MIR Drop is erased to Goto. | Actual normal and unwind drop-event semantics, liveness/resource resolution, drop glue and implicit field/callback cleanup. This requires a generic tool-level bridge or instrumentation with a correspondence argument; an annotation on Drop cannot fill this gap. Its eventual removal is not yet established to be small. |
| Open Buf/BufMut | Put explicit proof obligations on implementation methods and prove default bodies parametrically under those obligations. Temporary contracts may be attached to identified concrete implementations. | All in-crate implementations must refine them; downstream verified implementations must be checked. Runtime arbitrary implementations do not automatically satisfy byte-sequence laws. Do not trust blanket laws for all implementors. |
| Native weak refcount protocol | Preserve actual orderings and the reviewed generic weak-memory atomic/view rules. Local protocol obligations can be named and deferred under the new authorization. | Body proofs tied to original Data/Shared resources, promotion, registration, release sequence, Acquire recovery and final deallocation. An SC opening rule for Release-only access, or a fabricated Acquire witness, remains contradicted by saved controls and is inadmissible. |

Temporary trusted contracts can let original callers be checked **conditionally** while these obligations are open. They must not be reported as completed ownership/concurrency/destruction verification. A proof-preserving future replacement is plausible only when the final contract and resource model are already adequate; changing ghost parameters, invariants or representation later may force broad reproving. The current evidence does not establish small removability for Clone's ambient atomic authority or automatic Drop.

## Mutable reinterpretation boundary requiring an explicit audit

Current `src/buf/uninit_slice.rs` marks `new`, `uninit` and `uninit_ref` trusted and check(ghost). `new`/`uninit` return mutable wrappers and relate current/final byte or MaybeUninit views; `uninit_ref` is immutable. These are not automatically covered by the ordinary Vec DerefMut erasure control. Conversely D01's raw mutable B4 counterexample does not itself demonstrate these typed conversions are unsound. Record their TCB/effect-classification status and require exact program-input ghost-mutation rejection controls through the actual available wrapper methods/indexing, plus review of the unsafe `as_uninit_slice_mut` no-deinitialization condition. Do not assume a prophetic precondition cannot be discharged circularly; review its interaction with trusted initialized-input conversion postconditions. No such new test was run here.

## Recommended accounting and next architecture gate

Keep one original-representation invariant and a boundary ledger: exact source span, contract, reason (translation/effect model/mathematical protocol), positive caller scope, applicable counterexample, and concrete discharge condition. Separate raw primitive TCB from temporary bytes-specific assumptions. Preserve all existing evidence, but count modified ExclusiveBytes/explicit scoped-tree work as reusable components, not original implementation proofs.

Before more original-API expansion, require a conditional original-body path: construct actual BytesMut, freeze/share through actual representation, clone the actual Bytes handle, read across actual thread transfer, and account for actual last automatic destruction. Name every unresolved assumption on that path, including panic/unwind and external owner destructors. A successful conditional gate is useful dependency evidence; it is not the completed original-crate theorem. No experiment or source change is authorized by this document alone.
