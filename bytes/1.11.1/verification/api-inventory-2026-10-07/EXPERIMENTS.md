## Private features that remain outside current production

### Initialized mutable window and initialized scratch writer

Private source: `/workspace/bytes-initialized-window-probe/bytes/1.11.1/src/verified/exclusive.rs` and `src/verified/writer_adapters.rs`.

- `ExclusiveBytes::initialized_window(range) -> Option<&mut [u8]>` lends an in-bounds portion of already initialized bytes; fixed length, no allocation or copy. Reversed/out-of-range returns `None` without mutation. Upstream had ordinary mutable slice access and also the distinct `BytesMut::spare_capacity_mut` / `BufMut::{chunk_mut,advance_mut}` API. This candidate is not an uninitialized-spare-capacity implementation.
- `InitializedWriteWindow::{new,commit_prefix,discard}` allocates and zeroes separate scratch storage, exposes only initialized mutable bytes via Deref/DerefMut, then copies an accepted prefix into parent and explicitly closes scratch, or discards/ closes it. This is a safe concrete alternative for write staging, not `UninitSlice`.
- Latest private capture `/workspace/bytes-initialized-window-probe/captures/fifth-proof-input/`: proof log ends `Proved (358 files)`, native log 68/68, source tar SHA `2a122f09d16bae851bdc0bba55378f81c991d125ee9163e05cd0d9c9d270923d`. The candidate changes only `exclusive.rs` and `writer_adapters.rs` relative to its captured base. Intermediate failed captures are preserved; latest fifth run is positive, so earlier 3-VC or frontend errors are not the final status.
- Cost relative to upstream spare-capacity API: `initialized_window` is O(1) with no scratch; `InitializedWriteWindow` zero-initializes length L and copies accepted prefix P, O(L+P), with a second allocation. Upstream can expose spare allocation to the writer and publish initialized bytes without this zero-fill/copy. This feature is locally addable if the changed safe API is desired; it must not be called old `chunk_mut`/`advance_mut` coverage.

### Sealed generic read/write interfaces

A sealed subset does not satisfy legacy open-trait responsibility. Reopening would require an enforceable implementer contract and proved refinement, not renaming the sealed experiment.

## Soundness controls and wider ownership experiments

### Mutable access controls

The older raw B4 ghost mutable-access experiment is intentionally not reused for Vec-backed owners. `exact-current-805-ghost-derefmut-checker-reject`, SHA `892d6d5e1996cc81202631696772c704a85ac0e6ab92255d962f418adddba6b8`, records erased-write/native control mismatch and checker rejection. Related AsMut controls are `asmut-ghost-guard-rejects-owner-push-exit-1` SHA `696ab63db6f5f339972b01e8d4b8b88e0fcd3b1fca21f7e90e1a55268872cc9a` and `asmut-ghost-owner-borrow-rejected-with-native-control-exit-1` SHA `0af6049b38e47a0d04e7f1bbf374a7417da1f6dc6819a796b894db1c900286cb`. A ghost body attempting to mutate the ordinary Vec or borrow it mutably is rejected; native erasure leaves the byte unchanged. The accepted traits use ordinary runtime Vec borrowing and final mutable-borrow relations. These are soundness controls, not failed positive API bodies.

### Shared ownership and refcount protocols

The architecture decisions at `verification/ARCHITECTURE_DECISIONS.md` freeze several prior routes:

- D01: raw physical B4 mutable access classified as ghost (erasure changes behavior).
- D02: use of the stock SC invariant-opening rule for weak Release/Relaxed atomics (can extract permission without Acquire).
- D03: trusted universal laws for open `Buf`/`BufMut`.
- D04: bytes-specific ownership/refcount/last-owner/retirement theorems.
- D05: unchanged callback/static-pointer materialization and Clone shared-reference ticket splitting under stock tool support.
- D06: combining independent models/configurations as if they formed one integrated proof.
- D07: unchanged `State<T>::expected: Snapshot<(T,T)>` real spawn representation when non-Objective ownership is carried.

These matter to original `Bytes::clone`, O(1) slices/splits, arbitrary owner transfers, automatic reclamation, and concurrent sharing. The selected production route instead uses a single ordinary Vec owner, independent copied outputs, and explicit close. That is a substantial semantic/performance difference for persistent/shared operations, even though many byte-sequence functions remain available. The decision file explicitly says frozen methods may reopen only if the premise changes and forbids turning a renamed bytes ownership axiom into a primitive. This is not evidence that every alternative ownership implementation is impossible; it is evidence that the previous routes are outside the bounded local closure.

1. **Finish reference operator matrix**: Vec/slice forwarding already has a 334-file positive candidate and old Bytes compile-only checks establish several reference/array forms compile. Integrate only after writing the exact direction/type matrix and obtaining body proof for any uncovered directions. The existing generic forwarder does not cover `str`/`String` models and the negative-labeled legacy probe actually passed.
2. **Decide whether to add initialized range access**: `initialized_window` is a positive 358-file / 68-native private candidate with small source scope. It covers mutation of existing initialized bytes, not the upstream spare-capacity API. It can be added as a new safe utility if a real caller needs it, with no old `UninitSlice` compatibility claim.
3. **String operators**: current byte comparison semantics are available as four proved explicit copy helpers. Exact native operator syntax remains absent. Astra's review supports keeping stock char models and writing explicit byte semantics; broad DeepModel rewrites are a larger and riskier way to close this.
4. **Separate standard-trait closures**: `fmt::Write` may be a small adapter candidate over `append_str` but has no proof in these archives. `Hash`, `Debug`, Serde, native float bitcasts, open `Buf`/`BufMut`, unwind, and raw thread-scope routes all have actual contract, model, or tool boundaries and should not be represented as simple source omissions.

Do not treat changed method names as completion of the old API: `copy_clone` is not shared `Clone`; `try_copy_slice` is not O(1) `slice`; copied split is not zero-copy split; polynomial digest/hex are not Hash/Debug; bit wrappers are not `f32/f64`; sealed concrete cursor/writer helpers are not open `Buf`/`BufMut`; and `ReadableOwner` copy is not generic `Bytes::from_owner` transfer.
