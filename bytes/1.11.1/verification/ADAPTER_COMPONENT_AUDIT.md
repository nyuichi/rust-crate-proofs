# Adapter component audit

Scope: safe `Buf` adapters `Take`, `Limit`, `Chain`, `Reader`, `Writer`, and `IntoIter` in bytes 1.11.1 under vanilla Creusot 0.13. This is a component audit, not a full proof of the public generic adapters.

## Proof frontier

The reusable helper source in [`src/bounded_ops.rs`](../src/bounded_ops.rs) has isolated evidence: `bounded_len` returns mathematical `min(available, limit)`; `bounded_chunk` returns the exact input prefix of that length, including per-index byte equality in the probe; and `decrease_limit` returns `old_limit - count` when `count <= old_limit`. The bounded-ops probe includes the runtime source by path. The normal runtime calls these shared helpers. The correspondence checker records the reviewed inverse substitutions; the concrete `&[u8]` advance/copy proof remains specialized to that slice implementation.

These helpers support concrete local facts in `Take::remaining/chunk/advance` ([`src/buf/take.rs`](../src/buf/take.rs):134-148), `Limit::remaining_mut/chunk_mut/advance_mut` ([`src/buf/limit.rs`](../src/buf/limit.rs):58-73), and the count calculations in `Reader::read` and `Writer::write` ([`src/buf/reader.rs`](../src/buf/reader.rs):65-71; [`src/buf/writer.rs`](../src/buf/writer.rs):77-87). `Take::chunk` is proved as a prefix of the value returned by `inner.chunk()`; that alone does not establish a prefix of the whole unread buffer.

The generic implementations still depend on unmodeled `Buf`/`BufMut` behavior. Their trait methods have prose implementer notes but no Creusot contracts in [`src/buf/buf_impl.rs`](../src/buf/buf_impl.rs):115 onward or [`src/buf/buf_mut.rs`](../src/buf/buf_mut.rs):30 onward. A separate slim trait contract proves only a duplicate or restricted implementation unless it is connected to every runtime `Buf`/`BufMut` implementor. An extra private proof bound narrows the verified type set. A faithful generic byte proof needs a logical unread-byte view and method transition contracts, then has to establish them for the relevant implementations; `BufMut` additionally needs initialized-write and capacity facts.

## Candidate next steps

1. **Chain count aggregation.** Factor a safe runtime helper used by `Chain::remaining` and `Chain::remaining_mut` ([`src/buf/chain.rs`](../src/buf/chain.rs):135-137, 196-200). A precise postcondition is `result@ == min(a@ + b@, usize::MAX@)` over mathematical integers. This proves only the aggregation of the two reported counts.
2. **Chain count split.** Factor `from_a = min(a_remaining, count)` and `from_b = count - from_a` for `Chain::advance` and `Chain::advance_mut` ([`chain.rs`](../src/buf/chain.rs):147-163, 210-226). Specify `from_a <= a_remaining`, `from_a <= count`, `from_b == 0` when `count <= a_remaining`, otherwise `from_b == count - a_remaining`, and `from_a + from_b == count` in the mathematical model. This proves split arithmetic only. Inner bounds and state transitions need contracts for `Buf::remaining/advance` and `BufMut::remaining_mut/advance_mut`.
3. **Concrete slice composition.** Continue only where the proof includes the exact runtime `Buf for &[u8]` implementation ([`src/buf/buf_impl.rs`](../src/buf/buf_impl.rs):2889-2923). Scope any result to that concrete implementation; it does not prove arbitrary third-party buffers or `Bytes`.

Defer [`Chain::copy_to_bytes`](../src/buf/chain.rs:172-187) until allocation, `BytesMut::put/freeze`, ownership, and generic cursor transitions are modeled. Defer `Take::chunks_vectored` ([`src/buf/take.rs`](../src/buf/take.rs):158-184) until the `chunks_vectored` contract and the two reference-lifetime transmutes are covered. `Reader` and `Writer` byte-transfer results still need `Buf`/`BufMut` copy contracts. `IntoIter::next` ([`src/buf/iter.rs`](../src/buf/iter.rs):107-127) needs the nonempty-chunk law, one-byte advance transition, and an `IteratorSpec` describing the produced byte sequence.

## Chain-bound cfg experiment (not implemented)

The current vanilla translation stops on the recursive method bounds `Buf::chain<U: Buf>` at [`src/buf/buf_impl.rs:2416`](../src/buf/buf_impl.rs:2416) and `BufMut::chain_mut<U: BufMut>` at [`src/buf/buf_mut.rs:1345`](../src/buf/buf_mut.rs:1345); see [`verification/artifacts/logs/runtime-translate.log`](artifacts/logs/runtime-translate.log). In both bodies the method only constructs `Chain::new(self, next)` and does not call any method on `U`. Thus a proof-only signature with unconstrained `U`, selected under `cfg(creusot)`, could remove this specific bound from the translated trait. The normal build could retain the original signature. To avoid body drift, both signatures could be emitted from one macro with only the generic bound varying; a direct `cfg_attr` cannot remove a where-bound.

This is only a candidate to remove the reported frontmost translation blocker. It has not been compiled or proved. It makes the proof configuration's trait API wider than the executable API: a Creusot-only caller could construct `Chain<Self, U>` for a non-`Buf` `U`, though that value would not implement `Buf`. The method body is identical and all normal runtime builds retain the original bound, but the verifier would not be translating the exact trait signature. This would not supply byte semantics, prove adapter bodies, or establish source correspondence for methods beyond this signature. Further blockers may appear after translation proceeds; the existing run also records a comparison-model ICE, and `Buf`/`BufMut` cross-trait dependencies remain.

## Available standard-library facts and semantic limits

Repository [`src/std_specs.rs`](../src/std_specs.rs) specifies only `usize::try_from(u64)`. Bundled Creusot 0.13 slice specs at `creusot-libs/creusot-std/src/std/slice.rs` provide range indexing as an exact subsequence, `copy_from_slice` equality for equal lengths, and `split_first` head/tail facts. `core::iter::Iterator::next` has a production contract only when an `IteratorSpec` is supplied (`creusot-libs/creusot-std/src/std/iter.rs`:100-108). `creusot-libs/creusot-std/src/std/io.rs` has no `Read`/`Write` transfer contracts (only `_print`/`_eprint`), and no `size_hint`/`ExactSizeIterator` contract was found.

`Take::advance` checks only `count <= limit`; `inner.advance` may still panic if the count exceeds the inner remainder, and the limit decreases only after that call returns ([`take.rs`](../src/buf/take.rs):144-148). `Limit::advance_mut` has the same budget ordering and additionally relies on the unsafe caller to establish initialized bytes and the inner capacity ([`limit.rs`](../src/buf/limit.rs):69-73). Both `set_limit` methods may increase the budget after prior reads/writes; `get_mut` can change the inner cursor or capacity. `Reader::read` attempts exactly `min(remaining, dst.len())`; `Writer::write` relies on `BufMut::put_slice`. `Chain::advance` may consume `a` before a panic advancing `b`. Normal-return functional facts, panic paths, and unwind cleanup therefore remain separate obligations.
