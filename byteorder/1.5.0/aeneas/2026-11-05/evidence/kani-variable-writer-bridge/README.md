# Bounded original-writer bridge supplement

Four separate harnesses compare actual original byteorder 1.5.0 and byteorder-lite 0.1.0 BigEndian/LittleEndian write_uint/write_uint128 methods. Dependencies point at unchanged original source directories, use default std features and are fixed by Cargo.lock. Neither crate offers a serde feature; byteorder's named i128 feature is not enabled, while its u128 APIs are available. No Rust library source/manifest, pointer model or source adaptation is introduced.

For write_uint the domain includes every u64 value and nbytes1..8 for which the value fits in 8*nbytes bits; for write_uint128 it includes every u128 value and fitting nbytes1..16. Every harness quantifies over all initial [u8;32] arrays and all slice lengths nbytes..32. Both public methods receive the chosen prefix of separate identical arrays. Assertions require equality of the complete final 32-byte arrays and preservation of all bytes at indices nbytes..32, including the slice suffix and memory beyond the supplied slice. Full-width counts include every input value and avoid a width-overflowing shift in the fit assumption. Invalid counts, zero counts, insufficient buffers and non-fitting values are excluded.

Each harness runs independently under an outer60second limit with unwind34; successful unwind assertions are part of each log. Exact success/timeout/failed status, check counts and timings are in results.json and individual verification-{be64,le64,be128,le128}.log files. Kani0.68.0 uses Rust nightly-2026-08-21, while Aeneas extraction used nightly-2026-09-17. Exact host/LLVM compiler information is in rustc-version.txt. No identical-compiler-semantics claim is made across toolchains. Rust source/manifests are hashed before and checked after each run; Cargo.lock records resolution.

This is a bounded-allocation-shape normal-success comparison, not a proof for arbitrary allocations or unbounded buffer lengths. It does not verify failing-input behavior, perform a separate invalid-memory campaign or run Miri. No broader Rust memory-model guarantee is inferred from the checked assertions. Original byteorder remains blocked in Aeneas at raw-pointer construction and its unsafe body is not definitionally equal to the safe Lite body.

Lite's implementation is the comparison reference. Its independent Aeneas contract specifies the general-width byte encoder and suffix preservation. Together these results provide a scoped bridge for successful inputs and the specified32byte allocation shape; they add zero byteorder Aeneas API claims.

Run each separately with `bash verify-one.bash HARNESS LABEL`, using the names in src/lib.rs and labels be64/le64/be128/le128. Exit0 means completion; exit124 means timeout, which is unproved. Original BE64-only evidence is preserved in results-be64.json, README-be64.md, source-be64.rs (exact original source hash), verification-be64.log and exit-be64.txt. The current src/lib.rs contains all four harnesses; the original BE64 log predates that source extension. verify.bash preserves the original BE64-only invocation protocol.
