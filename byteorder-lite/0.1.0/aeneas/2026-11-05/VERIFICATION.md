# Exact integer and floating bit serialization, with explicit failure conditions

byteorder-lite 0.1.0: fixed-width unsigned and signed integer writes, plus BE/LE write_f32/write_f64, write their exact bit representations in the selected endian order and preserve trailing bytes when the output is long enough; shorter buffers panic before writing. Float proofs quantify over every 32/64-bit representation, including NaN payloads and signed zeros, under explicit bit-pattern and std to_bits models. No floating arithmetic is modeled. The two handwritten Default methods always panic. The four variable-width unsigned writers additionally have exact byte-count/space guards, selected-byte output on success and assertion failure otherwise.

F32/F64 are explicit 32/64-bit logical patterns; two executable std to_bits models preserve those patterns as unsigned words, with checked Lean value-preservation lemmas. Guards require original writer bodies and allow no other float operation. Kani checks std bit identity for every pattern and actual released writers with 6/10-byte buffers. Connecting these Rust checks to the Lean representation is reviewed, not mechanized; Rust nightlies differ. Official translation/standard integer and slice models, Lean, and Kani/CBMC are trusted. Mapped audits permit only propext, Classical.choice and Quot.sound.

This covers 30 selected writer methods, ten scoped integer readers, eight native-target identity conversions, and two handwritten Default methods, not all public APIs. Fixed-width reads, signed variable-width readers, remaining signed variable-width wrappers, other bulk and in-place conversions, I/O extensions, other targets and release extraction remain unproved. The float result establishes bit serialization only: floating arithmetic, comparisons, rounding, numeric accuracy, NaN arithmetic and signaling behavior are not modeled. Kani public-writer buffer lengths are fixed at 6 and 10; arbitrary valid slice lengths are quantified separately by the Lean theorems. Panic messages and unwinding side effects are not specified.

## Unsigned variable-width reads

The BE/LE `read_uint` and `read_uint128` proofs call the extracted original bodies directly. For every byte slice and byte count, normal return requires 1 through 8/16 bytes and enough input. The result is exactly the endian decoding of that prefix, padded with zero bytes on the high-order side. Invalid counts or insufficient input produce the modeled assertion failure. No custom standard model is introduced for these methods. Fixed-width reads that use `unwrap` remain blocked by the transitive official Formatter type axiom.

## Unsigned 24-bit default methods

Concrete original BE/LE read_u24 default bodies call the original read_uint body and cast. Their results equal the plain three-byte unsigned decode and are below 2^24; shorter input asserts. Concrete write_u24 bodies call original write_uint: value below 2^24 and output length at least three writes the exact three selected-endian bytes and preserves every suffix byte. Larger values or short buffers assert. All u32 values and all slice lengths are quantified. These proofs use concrete body contracts, not arbitrary callback assumptions, and add no standard models. Zero-padding and 24-bit bounds are proved with standard BitVec/Nat theorems; no native verifier axiom is accepted.

## Signed truncating writes

For every i64 input, BE/LE write_int with 1..8 output bytes and sufficient space writes the low 8*nbytes bits exactly and preserves the suffix. Its reference word value is the original two-complement bit pattern modulo 2^(8*nbytes). Signed representability is not a precondition. Zero byte count fails in a shift; count above eight fails in subtraction, both modeled as integerOverflow. A valid byte count with insufficient output produces assertionFailure. These conditions partition all counts and buffer lengths.

For every i32 input, BE/LE write_i24 writes the low 24 bits when at least three bytes are available and otherwise asserts. A checked sign-extension lemma proves the reference word value equals the original 32-bit pattern modulo 2^24, including negative and out-of-range values. Signed read_i24/read_int are covered by the additional exact signed-decoding contracts below.

The original write_int docs state that nonrepresentable values panic. The body theorems establish truncation under the actual count/space guards, and 176 native concrete public-call observations cover i32/i64 extremes, the signed 24-bit boundaries, and buffer lengths 0/2/3/5. This is a documentation/behavior mismatch, not a demonstrated memory-safety defect. write_i24 docs promise only short-buffer panic, so its truncation is not separately classified as a documentation problem. Native evidence is finite; universal claims come from the original-body Lean theorems.

## Signed prefix decoding

BE/LE read_int accepts byte counts1..8 with sufficient input and returns the exact two-complement decode at width8*nbytes of the selected-endian prefix. All invalid byte counts and insufficient inputs produce assertionFailure because the original read_uint guard executes before extend_sign. This differs from write_int invalid-count arithmetic failures. read_i24 returns the exact signed24 decode without loss in i32 and asserts on inputs shorter than3. Every prefix bit pattern, legal count and byte-slice length is quantified. Sign-extension, variable-width decoding and zero-padding equivalences use standard BitVec/Nat lemmas only; no custom model is added.

## Little-endian target conversion identities

On x86_64 little-endian/default features/debug extraction, LittleEndian from_slice_u16/u32/u64/u128 and from_slice_i16/i32/i64/i128 leave the entire mutable slice unchanged and return normally. The theorems quantify over every well-typed slice length and all element values, including empty slices, negatives and integer extremes. Opposite-endian conversion methods and other target configurations remain unproved.
