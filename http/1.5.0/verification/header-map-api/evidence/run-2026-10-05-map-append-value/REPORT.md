# `append_value` bounded proof pilot

This pilot proved the archived `append_value` COMA from the accepted Map attempt-6 source freeze. The target was not selected in the attempt-6 15-COMA lookup batch; it was independently bounded and proved here.

The COMA SHA-256 is `9e78217e81492788561261720835d27cce4ea7f8ee412abaa69c13cee9977f74`. Its provenance is Map source `9e2dbdc382acb0375d3d8592784077799386f75dc252205658759b2604610edf` and Name source `bc3be7d995c314b74f5aaca5b7259f9b7afd9dcd846b528264be1c43eb3ad5ca`, copied from `run-2026-10-05-map-functional-lookup/attempt-6-name-eq-open`.

The solver-free printer found five direct roots: one actual body root (`vc_append_value_T`) and four literal-true imported support roots (`vc_elim_Some`, `vc_index_mut_Vec_ExtraValue_T_Global`, `vc_len_ExtraValue_T`, and `vc_push_ExtraValue_T`). The fresh proof JSON has exactly the same five root names, each with a Z3 result. Thus the batch has five passing terminal roots, but only one is the `append_value` body. The imported support stubs do not prove the bodies of the corresponding Vec operations. This is conditional modular evidence for the recorded COMA, not a proof of other Map mutation operations or their supporting callees.

The archived COMA path was rejected by `cargo creusot prove` because it was outside the package `verif/` tree. That first invocation exited before starting Why3 or any VC. The retry copied the same archived bytes to the ignored, unique package path `verif/http_header_map_api_proof_rlib/header/map/append_value_resume.coma`; the live generated `append_value.coma` was left untouched. The retry passed all five roots with exit status 0 using the shared wrapper (one prover job, 1024 MiB limit).

At retry time, the package compilation used Map SHA `91dd661a5e40e9c15ace2ddd53bd64b50b1de21d04c785558658b2d8c296e202` and Name SHA `ed50c0e4bf945279fe497399e86ebbdbcf7f2a9a8aa58f7a1aab01ba5a6511ed`. The Map difference from the archived Map source is the pending public `get` postcondition; the append function body and its eleven recorded postconditions are unchanged. The live COMA had been regenerated with shifted source coordinates (SHA `40406433a410b276248d1a0619c4bd6b25d3db2dc89a262778fad854cc0263c6`). Its COMA bytes differ from the archived target. The independent audit printed complete Why3 task streams from both COMAs and found the raw stdout and stderr byte-identical, without normalization or goal filtering; this is a task-context consistency check, not the proof result itself. The successful proof remains a direct proof of the archived COMA bytes and source provenance above. `proof-context/coma-span-drift.diff` is diagnostic only.

Both scripts locate `verification/header-map-api` from their own path, then invoke `../../scripts/run-proof.sh` relative to that package directory.

`proof-validation.json` records the direct-root equality check. The independent audit is in `independent-astra-audit/REPORT.md` and `independent-astra-audit/report.json`. `proof.json`, `proof.log`, command files, COMA, source snapshots, source-span comparison, the arity task inventory, and the independent audit files are covered by `evidence-file-inventory.json`.
